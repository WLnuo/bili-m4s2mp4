# bili-m4s2mp4

把 B站客户端缓存的 `video.m4s` + `audio.m4s` 批量无损合并成可播放的 mp4 —— 不转码、不损画质、不删源文件。

[![Python](https://img.shields.io/badge/python-3.7%2B-blue)](https://www.python.org/)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)
[![Dependencies](https://img.shields.io/badge/dependencies-ffmpeg-orange)](#依赖)

> **⚠️ 这不是下载工具。**
> 本工具**不联网、不解析链接、不下载任何东西**，只做一件事：把你**已经缓存到本地**的
> m4s 碎片合轨成 mp4。需要下载功能请用 [BiliDownload](https://github.com/KafuuNeko/BiliDownload)
> 或 B站客户端自身。

---

## 这是什么

B站客户端（以及多数第三方下载工具）把视频存成 **DASH 分离流**：

```
video.m4s   ← 只有画面（AV1 / H.264）
audio.m4s   ← 只有声音（AAC）
```

单独拿出来都放不了，必须先合轨。`bili_m4s2mp4` 用 `ffmpeg -c copy` 直接复制码流、**不重新编码**：

- ⚡ **快** —— 一个视频 1~3 秒，比转码快几十倍
- 🎯 **无损** —— 画质音质与源文件完全一致
- 💤 **省** —— CPU 几乎不占用
- 🗂 **批量** —— 一次扫描整个缓存目录，几十集连续处理
- 📦 **零依赖** —— 纯 Python 标准库，不需要 pip install

适用于 **Windows 客户端 / Mac 客户端 / Android 客户端**的缓存目录（三者结构一致）。

## 特性

| 特性 | 说明 |
|---|---|
| **弹幕错误页拦截** | B站接口失败时会把 HTML 错误页存成 `danmaku.xml`，多数工具会当成弹幕复制给播放器导致报错。本工具校验格式后拒绝复制（实测 89 个分段里有 35 个中招） |
| **合集自动收纳** | 多集视频自动收进以视频标题命名的子文件夹，结构统一不混乱 |
| **弹幕同步** | `danmaku.xml` 复制到视频旁边并改成同名，播放器可直接加载 |
| **断点续传** | 已存在的成品自动跳过，中断后重跑不重复劳动 |
| **时长校验** | 合并后用 `ffprobe` 核对时长，防止产出坏片 |
| **空间预检** | 批量前累计预留空间，不会跑到一半才发现磁盘不够 |
| **坏源拦截** | 未下载完的占位文件（<10KB）直接跳过，不会合并出坏片 |
| **绝不删源** | 只新增 mp4 和弹幕，源文件原样保留 |

## 依赖

- **Python 3.7+**（只用标准库，无需 pip install 任何包）
- **ffmpeg**（含 ffprobe）

```bash
# Windows
winget install Gyan.FFmpeg
# 或 scoop install ffmpeg

# macOS
brew install ffmpeg

# Debian / Ubuntu
sudo apt install ffmpeg
```

验证：

```bash
ffmpeg -version
ffprobe -version
```

> 缺 ffprobe 也能用，只是跳过时长校验（会明确提示，不会误删成品）。

## 快速开始

```bash
# 1. 先预览，不写任何文件（强烈建议）
python bili_m4s2mp4.py --root "D:/bilibili/cache" --dry-run

# 2. 确认无误后正式合并
python bili_m4s2mp4.py --root "D:/bilibili/cache"
```

`--root` 支持两种层级，脚本会自动识别：

```
D:/bilibili/cache/
├── 116236176392460/          ← 一个视频/收藏夹（avid）
│   ├── c_36728737252/        ← 一个合集里的第 1 集
│   │   ├── entry.json        ← 元数据（标题、时长、集数）
│   │   ├── danmaku.xml       ← 弹幕
│   │   └── 80/               ← 清晰度目录（80=1080P, 64=720P, 32=480P）
│   │       ├── video.m4s
│   │       └── audio.m4s
│   └── c_36728737426/        ← 第 2 集
└── 726281380/
    └── c_xxx/ ...
```

也可以直接指向单个视频目录：`--root "D:/bilibili/cache/726281380"`。

## 输出结构

默认会把成品收进**以视频标题命名的子文件夹**，源缓存原样保留在视频目录下：

```
D:/bilibili/cache/726281380/
├── 【尚硅谷】大数据Apache Doris教程/    ← 新建
│   ├── 01-课程介绍.mp4
│   ├── 01-课程介绍.xml
│   ├── 02-Doris简介-概述.mp4
│   └── ...
└── c_712305030/ ...              ← 91 个源缓存目录
```

单集视频也一样处理，保持结构一致：

```
D:/bilibili/cache/230542581/
├── Tailscale玩法之内网穿透、异地组网..../
│   ├── Tailscale玩法之内网穿透、异地组网....mp4
│   └── Tailscale玩法之内网穿透、异地组网....xml
└── c_1185924608/
```

## 参数

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--root` | 路径 | 脚本所在目录 | 缓存根目录，可指向总目录或单个视频目录 |
| `--mode` | `title` / `part` / `both` | `part` | 文件命名模式，见下方说明 |
| `--out` | `top` / `c` | `top` | 输出到视频目录下 / 各分段目录内 |
| `--subdir` | `on` / `auto` / `off` | `on` | 子文件夹收纳策略，见下方说明 |
| `--danmaku` | `xml` / `both` / `off` | `xml` | 弹幕同步：只 xml / xml+pb / 不处理 |
| `--move` | 开关 | 关 | 把另一位置的同名 mp4 搬到目标位置 |
| `--dry-run` | 开关 | 关 | 只预览，不写文件、不建目录 |
| `--list` | 开关 | 关 | 只列出发现的缓存目录和分段数 |
| `--version` | — | — | 显示版本 |

### `--mode` 命名模式

**合集里所有分段的 `title` 是完全相同的**（都是课程全名），只有 `page_data.part` 不同。

| 模式 | 输出示例 | 适用场景 |
|---|---|---|
| `title` | `ExHyperV 1.4.1发布：Hyper-V 终极武器.mp4` | 单集视频 |
| `part` | `第一章-01-什么是Agent.mp4` | **合集（默认，推荐）** |
| `both` | `P02 第一章-01-什么是Agent.mp4` | 合集且想按页码排序 |

> ⚠️ **合集不要用 `--mode title`** —— 所有集共用一个标题，会互相覆盖，最后只剩 1 个文件。

### `--subdir` 收纳策略

| 值 | 行为 |
|---|---|
| `on`（默认） | 总是建 `<视频标题>` 子文件夹，单集也建 |
| `auto` | 只有合集（≥2 集）才建，单集平铺 |
| `off` | 全部平铺在视频目录下（旧行为） |

三者可随时切换。脚本会识别"目标位置没有、但另一位置已有"的成品，不会重复合并；加 `--move` 就把它搬过去（同盘是秒级重命名，不占额外空间、不重新编码）：

```bash
# 之前平铺过，现在想收进文件夹
python bili_m4s2mp4.py --root "D:/cache" --subdir on --move

# 反过来，从文件夹搬出来平铺
python bili_m4s2mp4.py --root "D:/cache" --subdir off --move
```

## 弹幕怎么用

弹幕文件（`.xml`）会和视频**同名放在同一文件夹**，这是弹弹play 的自动加载规则：

```
726281380/【尚硅谷】大数据Apache Doris教程/
├── 01-课程介绍.mp4
└── 01-课程介绍.xml     ← 同名同目录，打开 mp4 自动加载
```

### 用弹弹play 观看

[弹弹play](http://www.dandanplay.com) 是支持加载本地 xml 弹幕的播放器，Windows / macOS / Android / iOS 全平台。

**最简单的方式：用弹弹play 打开 mp4**，它会检测到同目录同名 xml 自动读取，无需任何操作。

如果没自动加载，用以下任一方式手动挂载：

| 方式 | 操作 |
|---|---|
| **拖拽** | 播放时把 `.xml` 文件从资源管理器拖到播放器窗口内 |
| **菜单** | 右键 → 弹幕列表 → 手动选择弹幕文件 |

脚本会自动跳过三类异常弹幕：

| 情况 | 提示 | 处理 |
|---|---|---|
| 源目录没有 `danmaku.xml` | `[无弹幕]` | 跳过 |
| 是 HTML 错误页（下载失败产物） | `[弹幕无效]` | **不复制** |
| XML 合法但 0 条弹幕 | `[弹幕为空]` | 复制，便于以后补充 |

> 第二类很隐蔽：B站接口偶尔失败会把错误页存成 `danmaku.xml`（通常 3400 字节，看起来像正常文件）。不校验的话会把 HTML 当弹幕塞给播放器，弹弹play 加载后直接报错。脚本检查文件是否以 `<?xml` 开头、是否含 `<i>` / `chatserver` 节点，不合法就跳过。

## 退出码

可用于脚本化流水线判断：

| 码 | 含义 |
|---|---|
| `0` | 全部成功 |
| `1` | 有失败或空间不足项 |
| `2` | 环境不完整（缺 ffmpeg）或根目录不存在 |
| `3` | 未找到任何缓存目录 |

```bash
python bili_m4s2mp4.py --root "D:/cache" || echo "有失败项，退出码 $?"
```

## 安全设计

这个脚本会写文件，所以每处操作都按"最坏情况不毁数据"来设计：

1. **不删源文件** —— 只新增 mp4 和弹幕，`video.m4s` / `audio.m4s` / `entry.json` 全部保留
2. **可重复运行** —— 输出已存在且非空就跳过，中断后重跑不会重复劳动
3. **绝不覆盖** —— 同目录重名自动加 `cid` 后缀，比较时忽略大小写（Windows 大小写不敏感）
4. **失败自清** —— ffmpeg 报错时删掉半成品，避免下次被误判为"已完成"
5. **校验后不合规才删** —— 时长偏差超过 3 秒视为失败并删除；但 **ffprobe 不可用时只警告不删**
6. **空间预检（累计）** —— 批量时累计预留，不会跑到第 50 个才发现磁盘不够
7. **坏源拦截** —— `video.m4s` 小于 10KB 视为未下载完/占位文件，直接跳过
8. **最高画质优先** —— 同一分段存在多个清晰度目录时取数值最大的，不会误选 480P
9. **目录只建不清** —— `makedirs(exist_ok=True)`，从不删除或清空已有目录
10. **弹幕与视频解耦** —— mp4 已存在时仍会独立补弹幕，无需重新合并

> 唯一的删除操作是"删掉本次自己刚生成的半成品或校验失败的 mp4"，从不碰源文件。

## 常见问题

**合并后磁盘占用翻倍？**
正常。`-c copy` 输出体积 ≈ 源 m4s 之和。确认播放正常后可删掉 `c_xxx/80/` 目录腾空间。

**视频播不了 / 黑屏？**
B站现在多用 **AV1** 编码，老播放器解不了。优先换播放器（[弹弹play](http://www.dandanplay.com) 内置多内核，AV1 支持良好）；确实要转 H.264 的话：

```bash
ffmpeg -i video.m4s -i audio.m4s -c:v libx264 -crf 20 -preset medium -c:a aac -b:a 192k out.mp4
```

转码慢、有损、体积可能更大 —— **能播就别转**。

**提示"未找到任何缓存目录"（退出码 3）？**
`--root` 要指向含 `c_xxx` 子目录的那一层。先用 `--list` 看看：

```bash
python bili_m4s2mp4.py --root "D:/cache" --list
```

**输出路径太长报错？**
Windows 传统路径上限 260 字符，长标题 + 嵌套子文件夹容易超。用 `--subdir off` 或少嵌套一层，或把 `--root` 指到更浅的目录。

**B站更新后缓存格式变了？**
缓存结构（`c_xxx/清晰度/video.m4s`）多年未变。若真遇到不兼容，欢迎提 issue 并附上目录树。
